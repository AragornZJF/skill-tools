# 验证清单（verification-checklist）

> 生成技能完成后的双层质量门禁。逐项执行，任何一项不过即迭代修复。

## Gate 1 · 静态自检（逐项 checkbox）

- [ ] frontmatter 合法：仅 name + description；name 只含字母/数字/连字符
- [ ] description 是**触发条件而非流程概述**（对照 skill-standards.md 反例自查）
- [ ] description 第三人称、含具体触发词/症状
- [ ] 目录结构完整：SKILL.md + 按决策流所需 scripts/reference/templates/assets
- [ ] SKILL.md < 500 行
- [ ] SKILL.md 含 Quick Reference 路由表（何时读哪个 reference）
- [ ] 引用文件路径真实存在（`bash ls` 验证）
- [ ] 分层自检三连：
  - SKILL.md 里出现公式让 Claude 算？→ 应移至 scripts/
  - 模板能约束的格式写进了指令？→ 应移至 templates/
  - 高频知识在 reference、低频细节在 SKILL.md？→ 对调
- [ ] allowed-tools 以注释形式给出建议（保持兼容性）
- [ ] 无 README/CHANGELOG 等辅助文件混入技能目录
- [ ] 命名合规：只含字母/数字/连字符，动词/动名词开头

## Gate 2 · 实跑试测

**步骤：**
1. **沙箱安装**：把生成的技能复制到隔离目录（不污染正式产物）。
2. **选场景**：1-2 个代表性场景（覆盖主触发路径 + 一个边界场景）。
3. **模拟新鲜代理执行**：仅依据该技能的 SKILL.md + reference 内容，对场景走一遍完整流程。
4. **检查**：
   - 指令无歧义、可无跳跃执行
   - 产出符合四层架构判断（该用模板的用了模板、该用脚本的用了脚本）
   - 有无指令缺口（读到某步不知道下一步做什么）
5. **结果判定**：
   - 通过 → 记录试测记录
   - 失败 → 回到实现迭代修复 → 重跑 Gate 1 + Gate 2（**最多 2 轮**）

**通过标准**：指令可无歧义执行，产出符合四层架构，无缺口。

## 诚实规则

- 两门皆过才标记"**验证通过**"。
- 2 轮迭代仍不过 → 交付"**未通过**"状态报告（含失败原因与建议），**绝不伪装验证通过**。
