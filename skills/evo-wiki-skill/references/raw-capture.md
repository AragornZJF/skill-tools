# Raw 层轨迹采集规程

Raw 层是进化的原料。没有真实的轨迹，后面的提炼和提案都是空转。本文件说明两种采集方式与记录标准。

## 方式一：任务结束后即时记录（首选）

任务完成后（用户说"记录一下"或你主动建议且用户同意），按 `assets/templates/raw-record-template.md` 写入：

```
<项目根>/.wiki-skill/raw/YYYY-MM-DD-<slug>.md
```

必填内容（宁短勿假，全部基于本次真实执行）：

- **任务目标**：用户要什么
- **使用技能**：加载了哪些 skill（没有则写"无"）
- **过程要点**：关键决策、工具调用、走过的弯路
- **结果**：成败与用户反馈
- **直接原因**：这次成败最直接的一两个原因（初步归因，最终根因由提炼环节确认）

不需要复述全部对话；但**关键报错原文、重要输出要原样摘录**——提炼环节靠这些做根因分析。

## 方式二：从会话日志回溯补录

用户想沉淀"之前某次"的经验时，用 session-logs 技能（jq 检索历史会话）找到对应会话，摘录关键内容后按方式一的格式补录。注意：

- 补录记录在文件头标注「回溯补录，来源会话：<id 或日期>」；
- 拿不准的细节标注「存疑」，不要编造。

## 记录纪律

- **只追加。** 写错不删原文，追加一条「修正：」条目（不变量 1）。
- **一次任务一条。** 超长任务可拆多条，文件名加 `-2`、`-3` 后缀。
- **及时。** 当天任务当天记，隔天记忆会污染事实。
- 记录完成后提醒用户：可以说「提炼」把轨迹沉淀为模式，或「进化一轮」走完整流程。
