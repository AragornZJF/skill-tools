# Wiki Layer 文件格式规范

所有文件格式以本文件为准；空白模板在 assets/templates/。

## 目录总览

```
<项目根>/.wiki-skill/
├── raw/                              # Raw 层：YYYY-MM-DD-<slug>.md
├── wiki/
│   ├── INDEX.md                      # 配置 + 模式索引
│   ├── patterns/P-001-xxx.md         # 一个模式一个文件
│   ├── logs.md                       # 进化日志（倒序追加）
│   └── skill-impact.md               # 技能改动台账（倒序追加）
├── staging/<技能名>/                  # 待门控的候选技能
└── archive/<技能名>/<日期>-<序号>/     # 被替换的旧版技能
```

## INDEX.md

上半部分是配置区，下半部分是模式表：

```markdown
# Wiki 索引

## 配置
- 技能目录: .agents/skills
- 已提炼水位线: raw/2026-08-31-fix-parser.md
- 下一个模式编号: 3

## 模式表
| ID | 标题 | 状态 | 出现次数 | 最近证据 | 关联技能 |
|---|---|---|---|---|---|
| P-001 | 改接口前未读调用方导致 breaking change | open | 2 | raw/2026-08-31-fe.md | api-client |
```

约定：

- **已提炼水位线**记录最后一条已分析的 raw 文件名，提炼步骤据此确定增量输入。它存在 INDEX 里而不是 raw 文件里，正是为了让 Raw 层保持不可变。
- **状态**取值：`open`（已确认、未修复）/ `proposed`（已有提案待门控）/ `resolved`（某次提案被接受后标记）。
- **下一个模式编号**由提炼步骤维护，保证 P-NNN 单调递增、不复用。

## Pattern 页（patterns/P-NNN-<slug>.md）

```markdown
# P-001：改接口前未读调用方导致 breaking change

- 状态: open
- 出现次数: 2
- 首次发现: 2026-08-30（raw/2026-08-30-api.md）
- 最近证据: 2026-08-31（raw/2026-08-31-fe.md）
- 关联技能: api-client

## 症状
执行时能观察到的现象，一句话说清。

## 根因
可操作的根因：缺什么检查、少读什么文件、错在哪一步。
不写"模型能力不足"这类无法执行的结论。

## 修复方案
具体到可直接写进技能的步骤。

## 证据
- [2026-08-30] 一句话概括（raw/2026-08-30-api.md）
```

## logs.md

倒序追加，每轮一条：

```markdown
## 2026-08-31 · 进化 #4
- 提炼: 分析 2 条轨迹，新增 P-003，更新 P-001
- 提案: 为 api-client 提交补丁（解决 P-001），待门控
- 门控: 已接受（测试 3/3 通过），已合并
```

某步没做就省略该行；一轮可以只做提炼。

## skill-impact.md

倒序追加，每次提案一条。**拒绝原因必填**——它是下一轮提案的避坑清单：

```markdown
## 提案 #7 · 2026-08-31 · api-client（补丁）
- 解决: P-001
- 改动: <diff 摘要，必要时贴关键 diff>
- 结果: 待门控 / 已接受 / 已拒绝
- 原因: <接受理由，或拒绝原因（必填）>
```

## PURPOSE.md（技能目录内）

回答"这个技能为什么存在"。新建技能必有；被补丁修改的技能同步追加演化记录：

```markdown
# PURPOSE

- 创建于: 2026-08-31 · 提案 #7
- 解决的模式: P-001（改接口前未读调用方导致 breaking change）
- 设计意图: 把"先查调用方"固化为一等步骤，而不是靠模型自觉

## 演化记录
- 2026-08-31 提案 #7: 初版
```

## tests.md（技能目录或 staging 目录内）

门控的测试集。每条含测试提示原文与可判断的期望行为；下方执行记录表逐次记录基线/候选的表现。模板见 assets/templates/tests-template.md。

## 命名约定

- Pattern 文件：`P-<三位编号>-<英文或拼音短 slug>.md`
- Raw 文件：`YYYY-MM-DD-<slug>.md`（超长任务拆条时加 `-2`、`-3` 后缀）
- 提案编号（#N）、进化轮次、模式编号全局单调递增，不复用
