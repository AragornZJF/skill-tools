# GTD 任务分诊

把用户给出的所有待办逐条过 GTD 决策流，每条必须落到唯一分类，最后输出分诊表。

## 决策流（逐条自上而下判断，命中即停）

1. **收集**：先列出用户提到的全部事项，保留原话，不做筛选。
2. **它可执行吗？**
   - 否 → 三选一：
     - **丢弃**：过时、无价值、不再想要
     - **参考**：不需要行动，但将来有用（资料、文章、线索）
     - **将来也许**：现在不会做，但某天可能激活（「以后再说」的点子）
   - 是 → 继续 3。
3. **需要多步才能完成吗？**
   - 是 → **立项拆解**：视为项目，给出第一个下一步行动
   - 否 → 继续 4。
4. **2 分钟内能做完吗？**
   - 是 → **立刻做**：直接做完，不记进清单
   - 否 → 继续 5。
5. **该如何处理？**
   - **有明确日期时间** → **日历**：标注具体时间，当天提醒
   - **近期就要做、无固定时间** → **热区清单**：下一步行动，动词开头，越具体越好
   - **该别人做或需他人先完成** → **等待**：注明对象与等待的事

## 八类速查

| 分类 | 判断问句 | 落点 |
|---|---|---|
| 丢弃 | 这事消失了我在乎吗？ | 从清单删除 |
| 参考 | 不用行动但要留档？ | 归档/收藏 |
| 将来也许 | 暂不做但可能复活？ | Someday 清单 |
| 立项拆解 | ≥2 步才能完成？ | 建项目 + 首个下一步行动 |
| 立刻做 | 2 分钟能完成？ | 马上做掉 |
| 日历 | 有固定日期时间？ | 日历 + 当天提醒 |
| 热区清单 | 下一步就能动手？ | 待办清单，动词开头 |
| 等待 | 关键环节在别人手上？ | 注明谁 + 等什么 |

## 输出格式

分诊完成后输出一张表 + 简短小结：

| 原任务 | 分类 | 建议动作 |
|---|---|---|
| （用户原话） | 八类之一 | 一句可执行的处理说明 |

小结包含：各类数量统计；「立项拆解」条目各列出第一个下一步行动；信息不足待确认的条目单独列出。

## 原则

- 每条事项按决策流自上而下只问一遍，命中即停，不重复判断。
- 信息不足以分类时不要猜：分类列写「❓ 待确认」，并在小结里追问一个最关键的问题。
- 保留用户原话描述任务，不润色、不合并多条任务。
- 2 分钟临界时宁可归「立刻做」：能顺手做完的事不值得记录成本。
